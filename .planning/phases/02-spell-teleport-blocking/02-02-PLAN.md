Extend SpellTeleportBlocker to handle Home Teleport (SPELL-02).

**The challenge:** Home Teleport appears as "Home Teleport" (or similar) in the menu target regardless of spellbook. The destination depends on which spellbook is active:
- Standard: Lumbridge (outside Varlamore)
- Ancient: Edgeville (outside Varlamore)
- Lunar: Lunar Isle (outside Varlamore)
- Arceuus: Dark Altar in Kourend (potentially inside Varlamore boundary)

**Implementation approach - detect active spellbook via widget groups:**

The spellbook interface that's currently open tells us which spellbook is active. RuneLite provides widget group IDs for each spellbook:
- Standard: `InterfaceID.SPELLBOOK` (or `WidgetID.SPELLBOOK_GROUP_ID`) = 218
- Ancient: `InterfaceID.SPELLBOOK_ANCIENT` (or equivalent) = check RuneLite API
- Lunar: `InterfaceID.SPELLBOOK_LUNAR` (or equivalent)
- Arceuus: `InterfaceID.SPELLBOOK_NECROMANCY` or Arceuus equivalent

**Simpler alternative (PREFERRED):** Since the menu click event fires on the spellbook widget itself, we can check which widget group the click came from via `event.getWidget().getId() >>> 16`. This tells us the spellbook without additional API calls.

**Add to SpellTeleportBlocker:**

1. Add a `Map<Integer, WorldPoint>` mapping spellbook widget group IDs to Home Teleport destinations:
```java
private static final Map<Integer, WorldPoint> HOME_TELEPORT_DESTINATIONS = Map.of(
    218, new WorldPoint(3222, 3218, 0),       // Standard -> Lumbridge
    // Ancient group ID -> Edgeville
    // Lunar group ID -> Lunar Isle
    // Arceuus group ID -> Dark Altar (Kourend)
);
```

NOTE: Look up the correct InterfaceID / WidgetID constants for each spellbook from the RuneLite API. The exact IDs may be available as `InterfaceID.SPELLBOOK` (218), and similar constants. If exact constants are not available or unclear, use the numeric group IDs directly with a comment explaining each.

2. Add method `isHomeTeleportBlocked(MenuOptionClicked event, BoundaryChecker boundaryChecker)`:
   - Extract widget group ID from `event.getWidget().getId() >>> 16`
   - Look up destination in HOME_TELEPORT_DESTINATIONS
   - If destination found: return `!boundaryChecker.isInVarlamore(destination)`
   - If destination not found (unknown spellbook): block by default (safer to block than to allow escape) and log a warning

3. Update `handleMenuClick` signature to accept `BoundaryChecker` as a parameter (or accept it in constructor). The method needs BoundaryChecker specifically for Home Teleport destination checking.

4. In `handleMenuClick`, after checking BLOCKED_SPELLS, add a check for Home Teleport:
   - If stripped spell name contains "Home Teleport" (or matches "Home Teleport", "Edgeville Home Teleport", "Lunar Home Teleport", "Arceuus Home Teleport" etc.):
     - Call `isHomeTeleportBlocked(event, boundaryChecker)`
     - If blocked: consume and send message
   - The home teleport variants may appear differently in menu targets. Research shows the standard one is "Home Teleport". For Ancient/Lunar/Arceuus, the menu target may still say "Home Teleport" since they all use the same spell but on different books. Use `.contains("Home Teleport")` for safety.

**Edge case handling:**
- If `event.getWidget()` is null: block by default (cannot determine spellbook = safer to block)
- If widget group ID not in our map: block by default and log warning for future investigation
- Arceuus Home Teleport destination (Dark Altar at ~1698, 3881, 0 or similar in Kourend): if this is inside the Varlamore boundary per BoundaryChecker, it will be allowed automatically. If not (placeholder regions may not include it), it will be blocked. This is correct behavior either way since the boundary data is the source of truth.
