Create new package `com.varlamoreuim.teleport` and class `SpellTeleportBlocker.java`.

This class is responsible for:
1. Maintaining a `Set<String>` of all blocked teleport spell names (no destination coordinate lookup needed since ALL of these spells go outside Varlamore)
2. Determining if a menu click is a blocked spell cast
3. Sending a chat message when a spell is blocked

**Key methods:**

- `handleMenuClick(MenuOptionClicked event, ChatMessageManager chatMessageManager)`: The main entry point. Returns true if the spell was blocked, false otherwise.
  1. Check `"Cast".equals(event.getMenuOption())` - return false if not a cast
  2. Strip color tags from `event.getMenuTarget()` using `.replaceAll("<[^>]*>", "").trim()`
  3. Check if stripped name is in BLOCKED_SPELLS set (O(1) lookup)
  4. If blocked: call `event.consume()`, send chat message via ChatMessageManager, log at debug level, return true
  5. If not blocked: return false

- `sendBlockedMessage(String spellName, ChatMessageManager chatMessageManager)`: Private helper.
  - Use `ChatMessageBuilder` with format: "Varlamore UIM: You cannot cast [spellName] - it would take you outside Varlamore!"
  - HIGHLIGHT color for "Varlamore UIM:" prefix, NORMAL for rest
  - Queue via `chatMessageManager.queue()` with `ChatMessageType.GAMEMESSAGE`

**Design notes:**
- Do NOT use BoundaryChecker/WorldPoint destination lookups. All 31 spells go outside Varlamore, so a simple name set is more reliable and maintainable than coordinate-based checking.
- Use `Set.of()` (Java 11+) instead of static block with HashSet if preferred, BUT note that `Set.of()` is immutable which is fine. However, `Set.of` does not allow duplicates and throws on null. Either approach works - use whichever is cleaner.
- The class should NOT be a singleton or use @Inject. It will be instantiated by the plugin.
